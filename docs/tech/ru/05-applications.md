# Приложения: страница планшета, TENGEN Tablet, TENGEN Desktop, установщик

У TENGEN (устройства, «палки») маленький экран и одно колесо. Всё, что требует больше места, делают четыре
программы вне прошивки:

| Программа | Где работает | Исходники | Как поставляется |
|---|---|---|---|
| **Страница планшета** (штаб, город, звук, настройки...) | любой браузер, внутри двух приложений ниже | `tools/webapp/` | gzip внутри прошивки (`src/web/tablet_page.h`) |
| **TENGEN Tablet** | Android | `app/` | `tengen_tablet.apk` (файл релиза) |
| **TENGEN Desktop** + монитор ПК | Windows, macOS, Linux | `tools/desktop/`, `tools/pc_monitor/` | `tengen_desktop.exe`, zip с `.app`, AppImage |
| **Установщик** | Chrome / Edge (Web Serial) | `tools/flasher/` | `flash_tengen.html`, один файл |

Все они говорят с устройством на одном протоколе (HTTP `/api/*`, поток SSE на порту 81 или тот же JSON по
USB-кабелю в строках с `@`); сам протокол описан в главе о протоколах. Эта глава — о том, как программы
устроены и почему именно так.

```
                 tools/webapp/src ──build.py──► tablet_page.h (gzip, во флеше прошивки)
                                                      │ устройство отдаёт его как /, /full, /tablet
        ┌─────────────────────────────────────────────┼───────────────────────────────┐
        ▼                                             ▼                               ▼
  браузер на телефоне/планшете               TENGEN Tablet (Capacitor)        TENGEN Desktop (pywebview)
  http://192.168.4.1/                        своя копия + самообновление      страница приходит по USB (@G) или
                                             с палки (/api/pagever)           http://192.168.4.1/full (Wi-Fi)
```

## 1. Страница планшета (`tools/webapp`)

### 1.1 Устройство исходников

Один офлайн-файл HTML, без фреймворка и без внешних запросов. `tools/webapp/src/index.html` — оболочка,
остальное подставляет сборка:

| Путь | Роль |
|---|---|
| `src/index.html` | шапка (логотип, меню, строка состояния), `#main`, холст `#boot`, модальное окно; метки `/*@INLINE path*/` |
| `src/hud.css` | вёрстка и интерфейс на DOM (настройки, кнопки-«чипы», переключатели) |
| `src/fonts.css` | создаётся `make_fonts.py`: подмножества WOFF2 в base64 |
| `src/core/` | `util.js` (кисти, текст, постэффекты), `theme.js`, `i18n.js`, `canvas.js`, `gl.js`, `store.js` (модель данных), `stream.js` (связь), `gps.js`, `boot.js`, `app.js` (вкладки, цикл кадров, качество) |
| `src/views/` | по файлу на раздел: `overview`, `hq`, `ble`, `wifi`, `sub`, `sound`, `pc`, `probe` (ИК / NFC), `astro`, `gallery`, `weather`, `settings` |
| `i18n/ru.json` | русский словарь (около 425 записей) |
| `mock.py` | «палка-пустышка» для разработки без железа (`python3 tools/webapp/mock.py page.html [порт] [denko\|kurenai] [en\|ru]`) |

Весь код делит один глобальный объект `T` (тема, помощники, список видов) и `S = T.S` (последние данные с
палки). Вид — объект, который кладут в `T.views`: `id`, `title`, `want` (какие потоки нужны), необязательные
`subs` (подвкладки) и `mount / frame / unmount`. Кнопки меню строятся из `T.views`.

### 1.2 Сборка: `build.py` -> `tablet_page.h`

`python3 tools/webapp/build.py` делает по порядку:

1. Читает `index.html` и заменяет каждую метку `/*@INLINE path*/` текстом файла после *лёгкой минификации*
   (`slim()`: убирает пустые строки, строки-комментарии и отступы; код внутри строки не трогает).
2. Заменяет `/*@DATA*/` данными неба (`T.DATA`: звёзды, линии созвездий, контуры суши, имена). Данные
   **разбираются из заголовка прошивки** `src/gallery/astrodata.h`, поэтому устройство и страница не могут
   разойтись.
3. Подставляет `@@VERSION@@` из файла `VERSION`.
4. Встраивает `i18n/ru.json` (всегда) и стартовый язык (`/*@LANG*/'en'`).
5. Падает, если остался внешний `src=`/`href="http..."`: страница должна работать без интернета.
6. Сжимает gzip уровня 9 с `mtime=0` (одинаковые байты при пересборке) и пишет `src/web/tablet_page.h`:
   `TABLET_GZ[]` (PROGMEM), `TABLET_GZ_LEN`, `TABLET_HTML_SHA` и комментарий `// html-sha256:`.

Сейчас: около 478 КБ HTML, 219 668 байт после gzip. В CI есть бюджет размера 231 000 байт для gzip (`build.yml`,
шаг «Size budgets»).

**Версия = SHA-256 несжатого HTML.** По ней и прошивка (`/api/pagever`, USB `@g ... begin`), и клиенты отвечают
на вопрос «моя копия актуальна?». Хэш берётся от HTML, а не от gzip: разные версии zlib дают чуть разные байты
gzip для одного и того же входа.

`--check` (шаг CI «Tablet page is up to date») пересобирает HTML в памяти и сравнивает только хэш, записанный в
`tablet_page.h`. Если исходник изменили, а заголовок не пересоздали, сборка падает с подсказкой «запусти
build.py». Другие режимы: `--html out.html --only-html [--lang ru]` пишет только HTML (и рядом `pagever.txt`) для
APK, mock-сервера и тестов, не трогая прошивку.

Прошивка всегда получает сборку со стартовым английским; язык переключается во время работы (следующий раздел),
поэтому одна страница обслуживает оба языка.

### 1.3 Языки: английский исходник, русский словарь

Тексты интерфейса в коде английские. `core/i18n.js` переводит **в точке вывода**:

- Холст: обёрнуты `CanvasRenderingContext2D.fillText / strokeText / measureText`. Поэтому раскладка меряет уже
  переведённый текст, а виду ничего не нужно знать о языках. В английском обёртка ничего не делает.
- DOM: строки проходят через `T.tr(s)` там, где вставляются (вкладки, настройки, диалоги).
- Явный выбор: `T.L('English', 'Русский')`.

Правила словаря (`ru()`): сначала точное совпадение; иначе известные фразы внутри строки заменяются (по границам
слов, длинные первыми, всё собрано в одно большое регулярное выражение); регистр сохраняется
(`DEVICES` -> `УСТРОЙСТВА`). Результаты кэшируются в `Map` (очищается после 4000 записей), так что на кадр
приходится несколько обращений. Фразы короче 3 символов сопоставляются только как целая строка.

Язык следует за устройством: `st.lang` из потока (проверка раз в 400 мс) вызывает `T.setLang()`, которая
очищает кэш обрезки текста, сохраняет выбор в `localStorage` и вызывает перерисовку через `T.onLang`.
`?lang=` перекрывает это для тестов. Тексты, которые приходят с устройства (страницы настроек, названия
вариантов), уже на языке устройства и при смене языка просто перезагружаются.

### 1.4 Рендер: Canvas 2D и один общий контекст WebGL

- **Canvas** (`core/canvas.js`): `T.canvas(parent)` создаёт непрозрачный (`alpha:false`) 2D-холст и
  `ResizeObserver`. Рисуем в CSS-пикселях, а размер буфера равен
  `min(devicePixelRatio, 3, T.RES / длинная_сторона) * T.RS`, где `T.RES = 1920` ограничивает длинную сторону,
  а `T.RS` — адаптивный множитель (раздел 1.5). Скрытый раздел (размер < 2 px) не пересоздаётся, поэтому картинка
  и память сохраняются.
- **Текст и кисти HUD** (`util.js`): `T.header`, `T.panel` (срезанные углы), `T.brackets`, `T.segBar`, `T.spark`...
  повторяют `ui.cpp` прошивки, чтобы планшет выглядел как палка. Единица `T.unit(W,H) = min(W/80, H/50)` даёт
  16 px на планшете 1280x800 и пропорционально масштабируется.
- **WebGL** (`core/gl.js`): *один* контекст на всё приложение, на внеэкранном холсте. Вид рисует сцену
  фрагментным шейдером (`T.GL.prog / begin / quad`), одним `drawImage` кладёт результат на свой 2D-холст, а
  HUD рисует сверху в 2D. Один контекст избавляет от лимита браузера на число WebGL-холстов и от пересоздания
  при смене раздела. Без WebGL (старый планшет, `?nogl`, потеря контекста) `T.GL.ok = false`, и виды рисуют
  прежнюю 2D-версию.
- **Темы** (`core/theme.js`): тема — это только палитра и шрифты (`T.C`, `T.RGB`, `T.HEAT`, `T.COOL`,
  `T.ALERT`, шрифты). Код рисования один и тот же, поэтому тема ничего не стоит в кадре. Три темы:
  `denko` (бирюзовый HUD), `kurenai` (чёрный / белый / красный, плоская: без свечения и сканлайнов) и `mono`
  (чёрно-белая, только на время запуска, пока тема палки неизвестна). Шейдеры WebGL написаны в цветах DENKO;
  в KURENAI одна функция в конце каждого фрагментного шейдера (`THEMED`) превращает бирюзовое и оранжевое в
  красное, а всё остальное в серое той же яркости (`T.GLK = 1`). Тема берётся из `st.theme` или `?theme=`.
- **Постэффекты** (`util.js`): свечение считается на уменьшенной в 4 и 8 раз копии, обе сводятся в одну
  маленькую «карту света» и накладываются одним проходом; градиент фона и слой сканлайнов с виньеткой
  предварительно рисуются один раз на размер. Правило: меньше полноэкранных перекрасок за кадр.
- **Шрифты**: JetBrains Mono (весь текст), Exo 2 (заголовки DENKO), Oswald (заголовки KURENAI) и
  подмножество IPAGothic только с глифами печати 天眼 и иероглифов штаба и погоды. `make_fonts.py` делает
  подмножества (латиница и кириллица из одной гарнитуры, чтобы ничего не сдвигалось при смене языка) и
  пишет base64 WOFF2 в `fonts.css`. Нужны `fonttools` и `brotli`; CI его не запускает.

### 1.5 Цикл кадров, 60 fps и адаптивное качество (`core/app.js`)

Один цикл `requestAnimationFrame`. `FPS_CAP = 60`: на экранах 120 / 144 Гц лишние кадры пропускаются, а после
подвисания цикл не догоняет пачкой (`dt` ограничен 0,1 с). Каждый кадр `S.tick(dt)` сглаживает данные
(они приходят рывками, а картинка течёт), затем работает `frame(dt, t)` текущего вида. Пока идёт заставка,
вид ждёт (`App.hold`), данные при этом продолжают приходить.

Качество подстраивается «как в играх», раз в секунду по измеренному FPS:

| Условие (проверяется каждую секунду, не при скрытой вкладке) | Действие |
|---|---|
| FPS < 50 две секунды подряд и `T.RS > 0.6` | разрешение `T.RS` -= 0.1 (холсты пересчитываются, видеокарта растягивает картинку) |
| всё ещё медленно, `T.RS` уже 0.6, три секунды | **LITE**: `T.Q.bloom = 0`, сканлайны выключены (единственный тяжёлый эффект) |
| FPS >= 58 восемь секунд подряд | `T.RS` += 0.1 до потолка |
| снова просело в течение 15 с после повышения | потолок снижается, чтобы не качаться туда-сюда |

Свежий старт (`App.fresh()`) происходит при каждой смене раздела или подвкладки: качество возвращается к
100 % с 2,5 с «на раскачку», так что деградирует только тот раздел, который действительно не тянет. Верхняя
строка показывает `NN FPS · 80% · LITE`, если включено «Show FPS» (Settings > Actions) или задан `?debug`.

Не путайте этот **LITE рендера** (свечение выключено) со **страницей LITE** (раздел 1.7): первый — автоматическая
ступень качества полной сцены, вторая — другая, лёгкая страница.

Разделы остаются живыми: `App.go()` прячет прежний раздел, а не уничтожает, и держит `KEEP = 3` последних;
самый старый выгружается. При возврате город появляется сразу, со всем, что в нём выросло. Последний раздел и
подвкладка запоминаются в `localStorage` (`view`, `sub_<id>`).

### 1.6 Канал данных (`core/stream.js`) и хранилище

Потоки, по предпочтению:

1. **SSE** `http://<палка>:81/stream?want=ble,wifi,...` (отдельный порт, чтобы медленная загрузка страниц не
   мешала). События: `st ble wifi snd sub pc sat wx ir nfc sens`. `want` задаёт текущий вид (`App.rewant()`), а
   устройство включает радио только под то, что смотрят.
2. **Опрос** `/api/*`, если SSE не открылся за 5 с: каждые 125 мс, по одному запросу (следующий только после
   ответа на предыдущий); палка получает `?tab=`, чтобы выбрать радио. Через 8 с снова пробует SSE.
3. **USB-мост** внутри TENGEN Desktop: `window.TengenUSB` (`want / api / poll`). `fetch()` на `/api/...` подменён,
   так что страница кабеля не замечает.

`core/store.js` (`S`) хранит последние данные и сглаживает их: `T.steady(мёртвая_зона, tau)` игнорирует дрожь
меньше порога, а большие изменения пропускает плавно. Здесь же **правила тревог**, общие для устройства и
приложения на компьютере: «новое» устройство (не виделось за сеанс, в пределах `al_newfor` секунд, достаточно
близко), разогрев после подключения (`al_warm`), тревога по трекерам и шкала активности (среднее по включённым
источникам с поправкой на чувствительность; пороги `al_warn` / `al_alarm`). Пороги — настройки самого
устройства (`/api/settings`, страница `alert`, перечитываются каждые 15 с). `tools/desktop/events.py` —
копия этих правил на Python.

Подписи устройств («мои AirPods»): их хранит палка и присылает 8-м полем каждой строки BLE; страница держит
локальную копию 6 с, чтобы новое имя было видно сразу (`S.setLabel`, `/api/label`). Диалог предупреждает, если
устройство меняет адрес (`stable:false`).

Раздел настроек (`views/settings.js`): чистый DOM, строится из `/api/settings` (страницы, пункты, типы
`enum / range / bool / info`); изменение применяется сразу и откатывается, если `/api/set` не прошёл.
Страница «Actions»: экран устройства, светодиоды, счётчик FPS и (только в приложении) проверка обновления.

### 1.7 Запуск: загрузка, заставка, выбор (`core/boot.js`)

При каждом открытии страницы идут три фазы (пропускаются с `?noboot`):

1. **Запуск** (чёрно-белая тема `mono`). Пять шагов со шкалой: `LINK` (поток открыт), `DEVICE` (первое `st`),
   `RADIO` (Bluetooth включён), `DATA` (первые устройства), `RENDER` (сцена нарисовала 3 кадра). Каждый шаг
   ждёт не дольше 6 с, так что без устройства сцена всё равно откроется. Когда первые четыре шага готовы,
   сцена Bluetooth > City монтируется под шторкой и прогревается во время заставки.
2. **Заставка** (2,7 с, как `core/boot.cpp` на палке): прицел, кольца, луч, «расшифровка» названия, печать
   天眼, развёртка. Тап пропускает её; при `prefers-reduced-motion` она пропускается. В её начале сразу
   включаются тема и язык палки (запасной вариант в `theme.js` через 9 с переключает на DENKO, если устройство
   не отвечает).
3. **Выбор** (только в браузере, открытом по корню устройства `/`; не в приложениях и не по `/full` или
   `/tablet`): две панели — **LITE** (лёгкая страница для телефона, переходит на `/lite`) и **FULL** (эта сцена).
   Пока выбираешь, город под шторкой продолжает расти, поэтому FULL открывается с готовым городом.

Входные адреса устройства (`src/web/web.cpp`): `/`, `/full`, `/tablet` отдают одну и ту же gzip-страницу (с
`Cache-Control: no-cache`); `/lite` и старый `/phone` — лёгкую страницу.

### 1.8 Страница LITE (`/lite`)

`src/web/web_page.h` — отдельная небольшая страница (около 27 КБ в прошивке, обычные строки; без gzip и
WebGL): шапка с зарядом, вкладки Overview, Bluetooth, Wi-Fi, Sub-GHz, Sound, System, Update. Каждая вкладка
опрашивает свои `/api/*` асинхронным циклом, следующий запрос только после ответа на предыдущий (интервалы:
3 с обзор, 2 с Bluetooth, 5 с Wi-Fi, 60 мс Sub-GHz и звук, 3 с система). Вкладки Sub-GHz и Sound держат радио /
микрофон включёнными, пока открыты. Язык задаёт устройство (`<html lang>` пишется при отдаче). Вкладка Update
загружает прошивку по воздуху (OTA). LITE нужна для старых телефонов и для тех, кому не нужна полная сцена;
у неё одна тема.

### 1.9 Параметры URL (разработка и тесты)

| Параметр | Действие |
|---|---|
| `host=ip[:порт]` | адрес палки (в приложении по умолчанию `192.168.4.1`, в браузере — хост страницы) |
| `sse=порт` | порт SSE (по умолчанию 81; mock-сервер использует 8091) |
| `theme=denko\|kurenai`, `lang=en\|ru` | зафиксировать тему / язык |
| `nogl` | отключить WebGL, принудительно 2D |
| `noboot` | пропустить запуск, заставку и выбор |
| `debug` | показывать FPS и состояние обновления |
| `shot` | для картинок README: все эффекты, без счётчика FPS и без адаптации |

## 2. TENGEN Tablet (`app/`)

Оболочка Android вокруг той же страницы. Capacitor 7.6.10, плагин `@capacitor/geolocation` 7.1.8, `minSdk 23`,
`targetSdk 35`, идентификатор `dev.tengen.app`. Оболочка нужна потому, что браузер не умеет того, что умеет
приложение:

- **Страница загружается из самого приложения** (`capacitor.config.json`: `androidScheme: http`,
  `cleartext: true`, `allowMixedContent`), поэтому может обращаться к `http://192.168.4.1` без проблем со
  смешанным контентом и origin (палка к тому же отвечает `Access-Control-Allow-Origin: *`). Когда планшет в
  Wi-Fi TENGEN, интернета нет, и он не нужен.
- **Экран не гаснет**, полноэкранный режим без системных панелей (`MainActivity.java`).
- **GPS** (`core/gps.js`, только при `T.native`): `watchPosition` с высокой точностью (`timeout 30000`,
  `maximumAge 15000`). Страница считает небо и глобус по этим координатам, и палка тоже их получает
  (`/api/loc?lat=&lon=`), чтобы её небо было «отсюда»: при первом фиксе, при сдвиге примерно на 1 км
  (0,009 градуса) или раз в 10 минут; при ошибке запрос повторяется. Прошивка проверяет числа
  (|lat| <= 90, |lon| <= 180, не оба нули) и вызывает `setGpsCity()`. В шапке видно `GPS ±12m`. Разрешения в
  манифесте: `INTERNET`, `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` (GPS не обязателен).
- **Без экрана выбора**: в приложении выбор LITE / FULL пропускается.

### 2.1 Сборка

Задача CI `android` (`build.yml`), локально так же:

```
cd app && npm ci && npm run sync     # sync = build.py --html www/index.html --only-html  +  cap sync android
cd android && ./gradlew assembleRelease
```

`www/` создаётся сборкой (в git не лежит); `pagever.txt` ложится рядом с `index.html` и упаковывается в ресурсы
APK. `versionCode` берётся из номера запуска CI (`APP_VERSION_CODE`), `versionName` — из файла `VERSION`.
`app/make_icons.py` перерисовывает иконки и заставку (печать 天眼) через Pillow и IPAGothic; запускать только
при смене картинки.

### 2.2 Подпись APK через секреты

Обновление ставится поверх старой версии, только если подпись та же, поэтому релизы подписываются одним ключом
TENGEN, которого **нет в репозитории**:

| Секрет | Содержимое |
|---|---|
| `TENGEN_KEYSTORE_B64` | хранилище PKCS12 в base64 |
| `TENGEN_KEYSTORE_PASSWORD` | его пароль (пароль ключа такой же) |

Шаг CI декодирует хранилище в `$RUNNER_TEMP/tengen.p12` и экспортирует путь как `TENGEN_KEYSTORE`.
`app/android/app/build.gradle` подписывает ключом с алиасом `tengen`, когда есть `TENGEN_KEYSTORE`, пароль и
файл; иначе берёт отладочный ключ Android. Правила: **релиз** (тег `v*` или ручной `release_tag`) без секрета
валит задачу; обычный пуш или форк только предупреждает и получает APK с одноразовой подписью: он работает, но
поверх официального не встанет (для Android это другое приложение).

### 2.3 Самообновление страницы с палки

В прошивке всегда лежит самая свежая страница, поэтому для изменений страницы новый APK не нужен. Новый APK
нужен, только если меняется нативная оболочка. Это делает `MainActivity.java`:

```
каждые 30 с, через 3 с после старта, через 1,5 с после возврата в приложение:
  GET http://192.168.4.1/api/pagever          (таймаут 2,5 с)   -> {"sha": "...", "gz": N}
  sha совпадает с текущей?  -> всё
  GET http://192.168.4.1/full                 (таймаут 15 с), распаковать gzip, если тело начинается с 1f 8b
  sha256(html) == sha ?  нет -> оставить старую страницу («bad hash»)
  записать filesDir/stickpage/index.html + pagever.txt (временный файл + переименование)
  сохранить путь как serverBasePath Capacitor, bridge.setServerBasePath(path) -> страница перезагружается
```

«Текущая» версия — это `pagever.txt` скачанной копии либо тот, что лежит в ресурсах APK. Проверка хэша
гарантирует, что недокачанная или повреждённая страница не включится. После обновления APK
(изменился `lastUpdateTime`) скачанная копия забывается: в новом APK страница может быть новее, чем на палке.
Состояние (`start`, `check`, `same xxxxxx`, `download`, `updated`, `bad hash`, `no stick: ...`) страница
получает через плагин `TengenUpdate` (`status()`, `check()`); с `?debug` оно видно в шапке как `UPD ...`, а в
Settings > Actions есть кнопка «проверить сейчас».

## 3. TENGEN Desktop (`tools/desktop`, `tools/pc_monitor`)

Одна программа: окно штаба (та же страница) + монитор ПК + трей, всплывашки и виджет. Python, окно на
**pywebview** (Windows: WebView2 / WinForms, macOS: WebKit, Linux: Qt WebEngine через PySide6, включается
`PYWEBVIEW_GUI=qt`). Данные пользователя лежат в `%APPDATA%\TENGEN`, `~/Library/Application Support/TENGEN`
или `~/.config/TENGEN`: `desktop.json` (настройки; ключ `alerts` хранит параметры всплывашек, виджета и окна),
`desktop.log`, `webview/` (хранилище браузера).

### 3.1 Файлы

| Файл | Роль |
|---|---|
| `tengen_desktop.py` | `Link` (USB), `Monitor`, локальный HTTP-сервер, стартовое окно, `App`, создание окна |
| `events.py` | «мозг» оповещений без окон и библиотек: `Engine.feed / pop / snapshot` |
| `overlay.py` | всплывашки, виджет, трей (`pystray`), `SseFeed`, единственный экземпляр, помощники Win32 |
| `overlay_html.py` | HTML всплывашек и виджета (DENKO / KURENAI, EN / RU) |
| `test_events.py` | тесты «мозга»; в CI идут на macOS и Linux |
| `fake_stick.py`, `render_preview.py`, `smoke_run.py` | помощники для разработки и CI |
| `build_exe.py`, `build_xplat.py` | сборки PyInstaller |
| `../pc_monitor/pc_monitor.py` | монитор: метрики, медиаклавиши, «сейчас играет», звук ПК, орбиты |

### 3.2 Режимы связи и стартовое окно

При запуске показывается небольшая стартовая страница (с `http://127.0.0.1:47321/`; если порт занят, берётся
следующий, до +19) с выбором **USB**, **Wi-Fi** и **АВТО** (USB, если устройство на кабеле, иначе Wi-Fi).
Последний выбор запоминается и запускается сам после обратного отсчёта. F11 — во весь экран, F2 — назад к
выбору, F3 — виджет.

- **USB**: всё по одному последовательному порту (CDC, 115200, DTR / RTS выключены, чтобы устройство не
  перезагружалось). Порт ищется по VID Espressif `0x303A`, затем по описанию (`jtag`, `esp32`), затем по имени
  (`/dev/ttyACM*`, `/dev/cu.usbmodem*`). Интернет на компьютере остаётся. Строки с `@` — протокол приложения:
  `@W want=...` (подписка; повторяется каждые 2 с как «я здесь»), `@Q id /api/...` (запрос) -> `@R id json`,
  `@E событие json` (события потока, тот же JSON, что в SSE), `@G id` -> `@g id begin размер sha`,
  `@g id смещение base64`, `@g id end` (страница: gzip кусками по 1,5 КБ в base64), `@X web` (раздел «Веб» на
  устройстве закрыт). Строки без `@` — линия монитора ПК (`PC ...`, `PV`, `KEY`, `AUD`).
- Страницу получают по кабелю, распаковывают, сверяют с SHA (до 3 попыток: изредка теряется 64-байтовый пакет USB,
  и страница «пришла не целиком» или gzip битый) и отдают окну как `/full` с небольшим внедрённым скриптом
  (USB-мост, клавиши F, язычок виджета у правого края). `Link.poll()` долгим опросом (0,25 с) отдаёт странице
  события.
- **Wi-Fi**: компьютер подключается к точке доступа устройства, окно открывает `http://192.168.4.1/full`. Если
  кабель тоже воткнут, монитор ПК продолжает работать по нему.

Язык окна: последний известный язык устройства (`st.lang`, хранится в `desktop.json`), иначе язык ОС
(язык интерфейса Windows, `AppleLanguages` на macOS, `LANG`).

### 3.3 Монитор ПК (`pc_monitor.py`)

Работает внутри Desktop (класс `Monitor`) или отдельно (`start_pc_monitor.bat`, который ставит `psutil`,
`pyserial` и необязательные библиотеки). Раз в секунду шлёт одну строку: `PC cpu= freq= c=<по ядрам> ram= ramu=
ramt= dsk= dr= dw= nd= nu= up= top= host= ts= tz= [bat= plug=]`; затем громкость (`PV vol= mute=`), строку «сейчас
играет» и **город процессов** (`PP`: до 24 программ — сначала самые занятые процессором, затем самые большие по
памяти, плюс активное окно; считается в фоновом потоке, потому что обход сотен процессов на Windows занимает
1-2 с). Раз в минуту шлёт орбиты спутников (`TLE`: МКС, Тяньгун, Хаббл с celestrak.org, обновление раз в 6 ч,
кэш в `tle_cache.txt`); `ts` / `tz` дают устройству точное время для неба.

Обратно устройство шлёт `KEY VOLUP|VOLDN|MUTE|PLAY|NEXT|PREV` (страница Media) и `AUD ON` / `AUD OFF` (раздел
Sound просит звук компьютера).

| Возможность | Windows | macOS | Linux |
|---|---|---|---|
| Медиаклавиши | виртуальные клавиши (`keybd_event`) | AppleScript: Spotify, затем Music; громкость системы | `playerctl` (MPRIS), громкость через `pactl` или `amixer` |
| Чтение громкости | `pycaw` | AppleScript | `pactl` / `amixer` |
| Название трека | системная панель медиа (`winrt`), иначе заголовок окна | Spotify / Music | любой плеер MPRIS |
| Звук ПК для Sound | WASAPI loopback (`PyAudioWPatch`) | недоступно (без драйвера loopback нет) | монитор PulseAudio / PipeWire (`sounddevice`) |
| Активное приложение в городе | да | нет | нет |

Звук ПК: 32 полосы спектра (60 Гц - 8 кГц, геометрически, те же границы, что у микрофона устройства), уровень,
волна на 64 точки и XY, около 30 кадров в секунду строками `PA ...`, с автоусилением; слушает только пока
устройство просит (таймаут 4 с).

На Linux для последовательного порта нужна группа `dialout`; если открыть порт не вышло из-за прав, стартовое
окно показывает подсказку `usermod -aG dialout`.

### 3.4 Оповещения: события, всплывашки, виджет, трей

**`events.py` («мозг»).** `Engine.feed(ev, data)` принимает те же события, что страница (`ble ir nfc sens wx st
snd`), и применяет те же правила, что `store.js`; `pop()` возвращает готовые извещения; `snapshot()` кормит
виджет. Пороги (`al_*`) приходят с устройства (`/api/settings`, перечитываются раз в 30 с), поэтому одинаковы на
палке, планшете и компьютере; собственные настройки приложения — `kinds`, тихие часы, лимит в минуту и т. д.
Защита от спама:

- разогрев после каждого (пере)подключения; вернувшееся устройство не «новое»;
- трекер рядом сообщается раз в 10 минут на устройство;
- извещения одного вида в пределах `merge_s` (2 с) склеиваются в одно («4 NEW DEVICES»);
- лимит `per_min` (6) в минуту, тревоги могут превышать его до двух раз; тихие часы (трекер рядом может их
  пробить);
- ИК: удержание кнопки — одно нажатие; NFC: та же карта в течение 5 с — одно касание; 433 МГц: первый снимок —
  только точка отсчёта; температура: изменение не меньше чем на 1 градус и не чаще раза в 10 минут; батарея:
  переход ниже 15 % не на USB; потеря / восстановление связи — только если состояние держится 5 с.

**Путь данных.** USB: `Link._push` -> `App.on_stick_event` -> `Engine.feed_raw`. Подписка — собственная
подписка страницы плюс `ble,ir,nfc,sens,wx` (`Link.set_extra`), поэтому оповещения работают, даже когда штаб на
другой вкладке или окно спрятано (у скрытого окна браузер притормаживает страницу). Wi-Fi: `SseFeed` открывает
собственный поток на `:81`. У устройства два места SSE для Wi-Fi-клиентов плюс одно USB-место, поэтому в режиме
Wi-Fi страница окна и поток оповещений занимают оба места; подключённый одновременно планшет вытеснит одно из
них. Для оповещений лучше режим USB. Тикер с частотой 5 Гц выдаёт извещения, обновляет виджет и раз в 5 с читает
тему устройства для выбора стиля.

**Всплывашки** (`overlay.Popups`): одно окно без рамки, поверх всех окон, со стопкой до 3 карточек; высота
подгоняется под стопку, пустое окно прячется; клик открывает штаб; угол и длительность — настройки. Стиль
следует теме устройства (DENKO: чёрная с оранжевыми полосами «осторожно», тревога красная и мигает; KURENAI:
чёрная с белой рамкой и косой плашкой-печатью) либо задан жёстко. Вариант «системные уведомления» использует
ОС (macOS через AppleScript, Linux через `notify-send`, Windows через уведомление `pystray`).

**Виджет** (`overlay.Widget`): мини-радар, шкала активности (平穏 / 活発 / 注意 / 警報) с метками по источникам,
температура за окном, последний пульт и карта, батарея и связь. Место и размер сохраняются, прозрачность и
«сквозные» клики — настройки. Виджет живёт самостоятельно: закрытие главного окна при включённом виджете или
трее прячет окно, а не завершает программу; выход — из меню трея или из меню виджета по правому клику.

**Трей**: меню `pystray`: открыть штаб, виджет, всплывашки, системные уведомления, сквозные клики, стиль, угол,
режим (USB / Wi-Fi / Авто), настройки оповещений, выход. Повторный запуск не открывает вторую копию, а показывает
окно первой (Windows: именованный mutex; macOS / Linux: проверка порта 47321; затем `GET /__app/show`).

**Автозапуск**: Windows `HKCU\...\Run`, macOS plist в LaunchAgents, Linux `~/.config/autostart/*.desktop`, с ключом
`--tray` (сразу в трей).

**Настройки и HTTP окна.** Настройки приложения лежат в `desktop.json` под ключом `alerts`: `popups`, `kinds{}`
(переключатели по типам), `quiet`, `quiet_from`, `quiet_to`, `quiet_trackers`, `per_min`, `merge_s`, `duration`,
`corner`, `style`, `native`, `widget`, `opacity`, `clickthrough`, `widget_rect`, `tray`. Локальный HTTP-сервер
окна отдаёт `/__app/prefs` (чтение), `/__app/prefs_set?k=&v=<json>` (запись одного ключа), `/__app/test_popup`
(кнопка «Проверить плашку») и `/__app/show` (повторный запуск). Без окна `tools/desktop/render_preview.py`
рисует демо-всплывашки и виджет на выдуманных данных (файлы открываются в браузере), а
`tools/desktop/test_events.py` проверяет «мозг»: разогрев и «текучка» из 75 устройств дают 0 плашек, новое
близкое устройство — 1, трекер, склейку, лимит, тихие часы, события IR / NFC / 433 МГц / температуры / батареи /
связи, разбор настроек и шкалу активности.

### 3.5 Особенности платформ

- **Windows**: WebView2 не рисует окно, созданное скрытым, поэтому всплывашки и виджет создаются видимыми и
  **паркуются за экраном** (`-32000, -32000`); «показать» — это перемещение. Прозрачность и сквозные клики —
  Win32 `WS_EX_LAYERED` / `WS_EX_TRANSPARENT`; `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` убирают окна из панели
  задач, Alt-Tab и из фокуса. Перетаскивание виджета — системное (`WM_NCLBUTTONDOWN` в потоке интерфейса формы
  после освобождения захвата мыши WebView2), оно плавное. Рабочая область для углов берётся из
  `SPI_GETWORKAREA`, делённой на масштаб DPI. EXE не подписан, поэтому SmartScreen может предупредить при первом
  запуске.
- **macOS**: перетаскивание виджета через `easy_drag` pywebview; трей работает отсоединённо в цикле Cocoa;
  программа не подписана Apple, поэтому первый запуск — правый клик > Открыть; звука ПК (loopback) нет.
- **Linux**: Qt WebEngine; перетаскивание виджета через `.pywebview-drag-region` (`easy_drag` на Qt ставит
  фильтр событий на всё приложение и приводил к падению); системные уведомления через `notify-send`; для трея
  нужен AppIndicator или X11.
- Статус проверок (автор, 17.11.2026): всплывашки, виджет и перетаскивание проверены на Windows (экран
  200 %); трей, системные уведомления, `focus=False` и прозрачность в WebView2 ещё не проверены; сборки macOS и
  Linux проходят дымовые проверки в CI, но с настоящим устройством не пробовались.

### 3.6 Сборки

| Цель | Скрипт | Результат |
|---|---|---|
| Windows | `build_exe.py` (PyInstaller `--onefile --windowed`, иконка, скрытые импорты `pc_monitor`, `events`, `overlay`, `pycaw`, `winrt`...) | `dist/tengen_desktop.exe`, в `build.yml` (задача `desktop`, `windows-latest`) |
| macOS | `build_xplat.py mac` | `.app`, упаковывается `ditto` -> `TENGEN-Desktop-mac.zip` |

macOS и Linux — отдельный workflow `desktop-xplat.yml`, запускается вручную (минута macOS стоит десять), с

## 4. Установщик (`tools/flasher`)

`flash_tengen.html` — **один файл**, в котором лежат и прошивка, и библиотека прошивки: пользователь открывает
его в Chrome или Edge, нажимает **«Установить прошивку»**, выбирает устройство и ждёт около минуты. Ни адресов,
ни файлов. Используется Web Serial и **esptool-js 0.5.4** (Apache License 2.0, `esptool-js.LICENSE`; текст
лицензии встроен в страницу).

### 4.1 Как он собирается (`make_flasher.py`)

Шаг CI «Make image and installer» сначала склеивает полный образ `esptool.py merge_bin`:

```
0x0 bootloader.bin   0x8000 partitions.bin   0xe000 boot_app0.bin   0x10000 firmware.bin   ->  tengen_full_0x0.bin
```

затем `python tools/flasher/make_flasher.py dist/tengen_full_0x0.bin dist/flash_tengen.html <тег>`:

- берёт `flasher_template.html` и подставляет: шрифты (те же JetBrains Mono и Exo 2, что на планшете, из
  `fonts.css`), тексты обоих языков, пакет esptool-js и прошивку в **base64**;
- esptool-js — ES-модуль, оканчивающийся на `export{...}`; скрипт заменяет эту строку на
  `window.__esptool={...}`, чтобы собственный модуль страницы мог им пользоваться;
- сначала проверяет образ (нулевой байт `0xE9`, сигнатура таблицы разделов `AA 50` по адресу `0x8000`), иначе
  отказывается собирать;
- проставляет версию и дату сборки; падает, если остался незаполненный `{{`.

Размер около 3,9 МБ; бюджет CI 4 150 000 байт. Язык страницы — по языку браузера (`localStorage` `lang`,
переключатель вверху): английский или русский.

### 4.2 Что записывается и почему настройки сохраняются

Установщик **не** пишет образ целиком. Раскладка образа: загрузчик (0x0), таблица разделов (0x8000), **NVS
(0x9000-0xE000, настройки устройства)**, otadata (0xE000), приложение (0x10000). Пишутся только две части:

| Часть | Адрес | Содержимое |
|---|---|---|
| 1 | `0x0` ... `0x9000` | загрузчик и таблица разделов |
| 2 | `0xE000` ... конец | otadata (`boot_app0`) и приложение |

Область NVS между ними пропускается. Стирание флеша в ней сбросило бы пользовательские настройки (язык, тема,
подписи, тревоги), поэтому обычное обновление их сохраняет. Остальное: `eraseAll: false`, `compress: true`,
`flashSize / flashMode / flashFreq: 'keep'`, скорость 921600 (обмен с ROM на 115200). Запись `otadata`
(`boot_app0`) вместе с приложением по адресу `0x10000` заставляет загрузчик запускать именно это приложение.

Ход на странице: фильтр порта `usbVendorId 0x303A` (Espressif) -> `ESPLoader.main()` -> чип должен оказаться
**ESP32-S3**, иначе «это не плата TENGEN» -> `writeFlash` со шкалой прогресса -> `loader.after()` (аппаратный
сброс) -> «Готово, отключите кабель и подключите снова». Ошибки: порт занят (закрыть TENGEN Desktop и другие
программы для порта: одним портом владеет только одна программа) либо сообщение с техническим журналом ниже.

Обновление по воздуху и откат — другой путь (OTA через раздел «Веб»; новая прошивка проходит пробный запуск, и
если за 15 с не заработала, возвращается старая); установщик нужен для первой установки, для восстановления и
тем, кто предпочитает кабель.
