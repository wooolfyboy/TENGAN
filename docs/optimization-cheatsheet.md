# Шпаргалка: генеральная оптимизация TENGAN перед публичным релизом

Рабочий документ для Claude (и для автора — посмотреть, как будет идти работа).
Перед публичным релизом файл удалить или перенести в описание PR.

## Что оптимизируется — все 5 частей проекта

| Часть | Что это | Где код | Как автор проверяет утром |
|---|---|---|---|
| **Прошивка палки** | то, что работает на T-Embed | `src/` | прошить установщиком `v2.0-test6`, пройтись по разделам |
| **Страница планшета** | веб-интерфейс, который палка раздаёт по Wi-Fi (`/full`, `/lite`) | `tools/webapp/` → вшивается в прошивку | открыть с телефона/планшета через Wi-Fi палки |
| **APK (Android)** | та же страница внутри приложения + GPS | `app/` (Capacitor), берёт страницу из `tools/webapp` | поставить `tengan_tablet.apk` из CI поверх старого |
| **EXE (Windows)** | TENGAN Desktop: штаб + монитор ПК | `tools/desktop/`, `tools/pc_monitor/` | запустить новый `tengan_desktop.exe` из CI |
| **Установщик** | HTML-страница для прошивки из браузера | `tools/flasher/` | прошить им палку (заодно проверяется сам установщик) |

Mac/Linux-сборки — тот же код, что EXE; на реальном железе их никто не проверяет, только CI.

## 0. Рамки ночной сессии (автор спит, ответить не может)

**Можно делать самому:**
- изменения без видимой пользователю разницы: скорость, память, размер, чистота кода, мусор, CI;
- маленькие коммиты в ветку `claude/loving-bardeen-c7rjcw`, каждый — собранный и проверенный;
- новые тестовые версии прошивки (`2.0-test6`, `-test7`, …) и установщики к ним в `dist/`.

**Нельзя без автора — только записать в отчёт как вопрос:**
- релиз, теги, слияние в `main`, force-push, переписывание истории;
- изменения поведения, внешнего вида, текстов, раскладки экранов, настроек по умолчанию;
- удаление функций, файлов из истории git, смена лицензий;
- смена языка комментариев (RU → EN) — это решение автора;
- всё, что меняет формат хранения в NVS (иначе сбросятся настройки у людей).

## 1. Принципы

1. **Сначала замер, потом правка.** Каждое изменение — с цифрой «было → стало». Нет цифры — нет оптимизации.
2. **80/20.** Сначала карта: где реально тратятся байты / RAM / время. Чинить самое крупное.
3. **Алгоритм важнее микротрюков.** Лишняя работа (перерисовка неизменившегося, опрос без нужды) — первый кандидат.
4. **Ничего не ломать.** Поведение не меняется. После каждого шага: сборка + проверки (раздел 4).
5. **Маленькие шаги, один смысл — один коммит.** Чтобы любой можно было откатить (`git revert`) или найти `git bisect`.
6. **KISS / DRY / YAGNI.** Упростить, убрать дубли, удалить мёртвое. Не писать «на будущее».
7. **Без переписывания ради переписывания.** Трогаю код только там, где есть измеримая польза или явная ошибка.
8. **Честный отчёт.** Что не проверено на железе — так и пишу.

## 3. Направления (по порядку приоритета)

### 3.1 Карта и замеры (без правок)
- Размер прошивки по символам: `xtensa-esp32s3-elf-nm --size-sort -S -C .pio/build/t-embed-cc1101/firmware.elf | tail -50`
  (тулчейн: `~/.platformio/packages/toolchain-xtensa-esp32s3/bin/`). Топ крупнейших таблиц/функций.
- Что попадает в RAM (`data`/`bss`): большие массивы без `const`, буферы, которые можно отдать в PSRAM.
- Статический анализ: `cppcheck --enable=warning,performance,portability src/` и `ruff check tools/`.
- Мёртвый код: функции/файлы без вызовов, неиспользуемые ресурсы (шрифты, картинки, словари).
- Страница планшета: что занимает байты (шрифты, CSS, JS, словарь RU).

### 3.2 Прошивка (src/)
- `const`/`PROGMEM` для таблиц — освободить RAM.
- Нет `malloc`/`new`/`String`-склеек в горячем цикле (фрагментация кучи при долгой работе).
- Нет блокирующих `delay()` и долгих ожиданий в главном цикле.
- Перерисовка экрана — только при изменении; частота опроса радио/датчиков — разумная.
- Логирование минимум с `heap_caps_get_minimum_free_size` — следить за минимумом памяти, не за текущим значением.
- Предупреждения компилятора: собрать с `-Wall -Wextra`, разобрать реальные проблемы.
- Логика визуала (экран палки, анимации страницы): оптимизировать КАК рисуется, результат — пиксель в пиксель тот же.
  Идеи по самому дизайну — не делать, а записать в отчёт разделом «Идеи по визуалу».
- Повторяющиеся куски экранов → общие функции (`uiHeader` и т.п. уже есть — использовать везде).

### 3.3 Страница планшета (tools/webapp) и установщик (tools/flasher)
- Убрать неиспользуемые правила CSS, функции JS, глифы шрифтов (сабсет только нужных символов).
- Анимации — CSS, без лишней работы с DOM в циклах/таймерах.
- После правок: `python tools/webapp/build.py` и `--check`, размер gzip — в отчёт.

### 3.3a APK (app/)
- Страница внутри APK — та же, что на палке: оптимизация 3.3 попадает сюда автоматически (`npm run sync`).
- Размер APK (сейчас ≈ 3.7 МБ): включить сжатие ресурсов/R8, убрать неиспользуемые плагины Capacitor.
- **Не менять** ключ подписи и `applicationId` — иначе APK не встанет поверх старого.
- Сборка только в CI (`build.yml`, job `android`) — проверить, что зелёная, размер APK — в отчёт.

### 3.4 TENGAN Desktop (tools/desktop, tools/pc_monitor)
- AppImage/.app: вместо `--collect-all PySide6` — только нужные модули (QtCore, QtGui, QtWidgets,
  QtWebEngine*, QtWebChannel, QtNetwork, QtPositioning, QtPrintSupport), исключить Multimedia, Qml/Quick, 3D,
  TextToSpeech, Sql, Nfc и т.п. Цель — в разы меньше 273 МБ. Проверка: шаг self-test в CI должен остаться зелёным.
- Опрос монитора ПК — не чаще нужного, без лишней нагрузки на CPU.
- `ruff`, мёртвый код, дубли между Windows-сборкой и xplat.

### 3.5 Репозиторий и CI
- Мусор под отслеживанием git (`git ls-files`): временные файлы, `__pycache__`, лишние картинки.
- Кэш в CI, отсутствие лишних шагов; Node 20-предупреждения в actions (обновить версии actions).
- **Бюджеты размеров в CI**: прошивка, страница планшета, установщик — шаг падает при превышении (порог = новое значение + запас ~5 %).

### 3.6 Документация (подготовка, без смены смысла)
- README понятен человеку «с нуля»: что это, как прошить, как пользоваться.
- Проверить, что нет личных данных, путей автора, токенов (`git grep -i` по почте/ключам/паролям).
- Лицензии сторонних шрифтов и библиотек на месте.

## 4. Проверки после каждого шага

```bash
pio run                                   # прошивка собирается
pio run -t size                           # цифры для отчёта
python tools/webapp/build.py --check      # страница планшета актуальна
python tools/desktop/test_events.py       # логика десктопа
python -m py_compile tools/desktop/*.py tools/pc_monitor/pc_monitor.py
```

Сборка образа и установщика для теста на палке:

```bash
B=.pio/build/t-embed-cc1101; APP0=$(find ~/.platformio/packages -name boot_app0.bin | head -1)
esptool.py --chip esp32s3 merge_bin -o dist/tengan_full_0x0.bin 0x0 $B/bootloader.bin 0x8000 $B/partitions.bin 0xe000 "$APP0" 0x10000 $B/firmware.bin
python tools/flasher/make_flasher.py dist/tengan_full_0x0.bin dist/flash_tengan_v2.0-testN.html v2.0-testN
```

Версия: `VERSION` и `src/core/version.h`, затем `python tools/webapp/build.py`.
После пуша — проверить CI: `build.yml` (прошивка) и `desktop-xplat.yml` (mac/Linux).
